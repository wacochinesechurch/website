# Waco Chinese Church · 韦科华人教会

A rebuilt bilingual website for a non-denominational Chinese church in Waco,
Texas, founded in December 1993 as a Baylor University student fellowship.

```bash
npm install
npm run dev      # http://localhost:4321
npm run build    # → dist/
```

Requires Node 20+.

---

## What this is

Static HTML, generated by Astro, deployable free to any static host. About **2.3 KB of JavaScript** in total; the homepage is **~8 KB gzipped**, and
the fonts are self-hosted and subset (70 KB on /en, 293 KB on /zh — down from
1.8 MB and 2.7 MB via Google Fonts). No third-party requests at all.

Content lives in `src/content/` as Markdown and YAML, edited by church
volunteers through a CMS at `/admin`. There is no database, no server and no
monthly bill. If every tool in this stack disappeared, every word the church
has written would still be sitting in the repository in readable files.

## The two rules the whole design rests on

**1. Time-sensitive content carries its own expiry.**
An event knows its own date and demotes itself once it has passed. A notice
carries `showUntil` and vanishes on its own. The previous site rotted because
taking things down was a manual job nobody remembered — on 21 September 2026 it
was still advertising a Lunar New Year party as happening "this Sunday".

Three layers enforce this: build-time filtering (`src/lib/church.ts`),
read-time re-checking in the visitor's browser (`src/scripts/freshness.ts`),
and a nightly rebuild so the HTML crawlers see stays honest too.

**2. Nothing is invented.**
Every factual claim traces to the church's own published material. Where
something could not be verified — the meeting time of any fellowship, a phone
number, a statement of faith, who leads the church — the site omits it and says
how to ask, rather than guessing. Those gaps are listed at **`/en/review`**, a
noindexed checklist generated from the content itself.

See [`docs/FACT-AUDIT.md`](docs/FACT-AUDIT.md) for what was verified, what was
stale, and the eleven contradictions found in the source material.

## Bilingual

`/en/...` and `/zh/...` are parallel and equal; neither is a translation layer
over the other. The language switch preserves the current page. Every
translatable field is `{ en, zh }` in **one** content file, so a volunteer
creates one event and gets both languages — an orphaned translation is
structurally impossible.

## Layout

```
src/
  content/          the words and facts — edit these, not the code
  pages/[lang]/     one file per page, rendered for both languages
  components/       reusable pieces
  styles/tokens.css the design system: colour, type, space, motion
  i18n/             locale routing, date formatting, UI strings
  lib/church.ts     data access and the "is this still upcoming?" logic
  scripts/          all ~2.3 KB of the site's JavaScript
public/
  admin/            the CMS volunteers use
  _redirects        old Squarespace URLs → new homes, plus language negotiation
```
